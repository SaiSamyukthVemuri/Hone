# Test a paid Hone signup

Use an isolated Hone app and database with the draft signup branch and apply migration 0387 (signup) followed by 0388 (team seats) and 0389 (owner tier changes and immediate cancellation). Keep the production rollout flag off. The sandbox billing account is Hone Care inc sandbox. Stripe’s invoice previews returned USD 49.00 for Solo and USD 99.00 for Studio at quantity one, with automatic tax off. These previews did not collect payment. The owner portal configuration supports invoices and payment-method updates.

| Sandbox setting | Value to use |
| --- | --- |
| `HONE_STRIPE_PRICE_SOLO` | The existing Solo recurring USD 49.00 price ID |
| `HONE_STRIPE_PRICE_STUDIO` | The existing Studio recurring USD 99.00 price ID |
| `HONE_BILLING_ACCOUNT_ID` | The US billing sandbox account ID |
| `HONE_BILLING_PORTAL_CONFIGURATION` | The sandbox configuration for invoice history and payment method updates |


Install the billing sandbox API key as `HONE_BILLING_STRIPE_SECRET_KEY` in the test app's runtime secret store. Set `NEXT_PUBLIC_APP_ORIGIN` to the test app’s HTTPS origin and allow its auth callback on the matching test Supabase project. Register the app's HTTPS `/api/billing/webhook` as an event destination for this **platform account** for `invoice.paid`, `invoice.payment_failed` and `customer.subscription.deleted`. Install its signing secret as `HONE_BILLING_WEBHOOK_SECRET`. For a local forwarded endpoint use the signing secret printed by the listener. Set `HONE_SELF_SERVE_CHECKOUT_ENABLED=true` only on the isolated app. Studio treatment payments use a separate integration.

On the test auth project set the Site URL to the app origin, allow the signup and auth callback URLs (including the plan return query), and enable Google sign-in with the test provider credentials. Install the contents of `supabase/templates/sign-in.html` as both the Confirmation and Magic Link templates for the sandbox project. The tracked `supabase/config.toml` is the production configuration and does not reference them. To see the sign-in email on a LOCAL stack, copy the config into an owned stack directory and add these two blocks there (never to the tracked file): `[auth.email.template.magic_link]` and `[auth.email.template.confirmation]`, each with `subject` ("Your Hone sign-in" and "Your Hone sign-in code") and `content_path = "./supabase/templates/sign-in.html"`.

1. From the Hone homepage use Try Hone, or Sign up in the mobile menu. On Pricing choose Solo or Studio once. Sign in with Google or type the code delivered to the test inbox. Confirm the same tier and price appear on the studio details screen. Enter the owner and studio names. Checkout shows the monthly price, with automatic tax off for this exercise.
2. Pay with a Stripe test card. Opening the return URL alone grants nothing. After the paid invoice is verified, the return page automatically opens the dashboard with the owner setup wizard. Close the tab during checkout return and verify Open your studio on the login page also reaches the same setup. Re-deliver the same invoice event and verify there is exactly one active owner membership and one studio. Repeat on the other plan with another test identity. In the owner wizard use Configure availability, save weekly hours on Settings → Availability, then return to studio setup. Finish the wizard and choose Open calendar. Verify the hours in the existing studio calendar and confirm a missing consultation service or live treatment consent form points to its actual settings page.
3. As the owner, open Settings → Billing. Check the plan, monthly price, seat allowance and Active status. Use Update card to change the sandbox payment method, then open View invoices and receipts. Run a sandbox renewal and confirm its successful payment used the replacement card. For a failed renewal verify that the first failure starts 168 hours of normal access. Subsequent failures on that invoice preserve the original deadline. At the deadline new appointments and chart entries pause. Confirm the owner can read records and reach billing. Use Pay outstanding invoice for the overdue renewal and verify the invoice in Stripe belongs to that studio. After the signed payment event, refresh Billing and check that the same studio can book and chart again. Verify that a practitioner cannot see Billing in Settings or use its actions. If using a Stripe test clock, advance the app/database test clock consistently for the deadline check.
4. Run the database regression with `npm run test:db -- tests/db/paid-studio-signup.db.test.ts`. It signs local event fixtures, exercises concurrent delivery and uses real PostgreSQL transactions. Stripe reads in this test are simulated.

5. Open Settings → Team as the paid owner. Solo starts at 1/1 practitioner seats with no receptionist. Studio starts at 1/3 practitioners with its one included receptionist seat. The receptionist seat is a Front Desk seat grant (the plan writes it when the studio is created or changes plan, and withdraws it on Solo); billing NEVER lists a studio for Front Desk, so on the isolated stack an operator sets the rollout to `pilot` and adds that one studio (the existing rollout commands) before the invitation works, and every other studio stays off, and a second receptionist or any receptionist on Solo is refused. Invite two practitioners and one receptionist. Pending invitations reserve seats, including an invitation for another owner. Accept an invitation, revoke another and refill it. Attempt two simultaneous invitations for the last seat and verify only one invitation is stored.
6. Run `npm run test:db -- tests/db/subscription-team-seats.db.test.ts` for the checked limits, reactivation, concurrency and plan transitions. Use a Studio with extra practitioners, a receptionist and a pending invitation. Select Solo and verify the affected roster. After the subscription owner confirms, Hone keeps the subscribing owner, deactivates the other studio memberships and revokes every pending invitation automatically. A refused Stripe change leaves the team intact. Check a signed-in staff session on its next request, open historical appointments as the owner, and verify the same staff member can still work in another studio. Upgrading again opens seats for new invitations. In Settings → Billing, use Change tier to move between the two tiers. Seat limits take effect when confirmed. The new monthly price starts at the next renewal, without a mid-cycle charge or credit. Use the existing Settings → Team invitations and the staff welcome from #1801 in the test app. Enable HONE_STAFF_ONBOARDING_ENABLED for that introduction. Confirm an invited practitioner opens their calendar and an invited receptionist opens the front desk.

Keep the production activation conditions in HON-70. Existing pilot agreements and treatment charges have separate ownership. For a sandbox rollback, undo 0389, then 0388, then 0387. Reconcile any pending change before rollback. Database rollback cannot recreate a canceled Stripe subscription. The signup rollback refuses to delete active or pending purchase history.

### Owner cancellation and recovery

Confirm **Cancel subscription now** with a synthetic owner. Verify studio access pauses on the next request in a second signed-in staff session, owner Billing and invoice history still open, and the test subscription in Stripe is canceled immediately. An overdue invoice paid later must leave a voluntary cancellation in place. Check a second studio on the same login still works. From the canceled studio’s Billing page, choose Restart and pay for the former tier. Verify that the studio ID, team, appointments and records are retained, that one new subscription is bound to the existing billing customer, and that a delayed event for the canceled subscription cannot pause access again. Open View invoices and receipts for the customer’s full history.

Use the test app’s authenticated scheduler to call `GET /api/cron/subscription-changes` every minute with its own `CRON_SECRET`. This retries interrupted owner requests. Simulate a Stripe outage during cancellation and verify that studio access pauses while Billing says cancellation is pending. Restore connectivity and verify Stripe and Billing reach Canceled. Use Hone as the entry point for tier changes so the tier and team-access changes are applied together. Keep tier switching disabled in the Stripe portal.

### Subscription emails

The US subscription sandbox uses Hone as the sender for first-payment and monthly receipts, first missed-renewal notices, and overdue access pauses. Use one synthetic verified owner with a private test inbox. Set `HONE_BILLING_TEST_RECIPIENT` to that owner's address in the isolated app. An empty value disables dispatch. The signed invoice and its email intents commit together. An authenticated worker checks the current owner and invoice again before sending. For receipts it links to the Stripe-hosted invoice where both PDFs can be downloaded. Configure the sandbox for one receipt sender to avoid duplicates with Stripe's own customer emails.

Point an isolated scheduler at `GET /api/cron/subscription-emails` on the **test app**, every five minutes with its own `Authorization: Bearer <CRON_SECRET>`. Use the existing VPS or external scheduler for this cadence. The database enforces the deadline even when nobody opens Hone. The first worker run after that deadline can send the pause email. Confirm scheduler success and inbox delivery as part of hosted acceptance.

1. Pay the first invoice and one monthly renewal. Verify two receipts with the actual invoice numbers, periods, taxes, totals and PDF access. Replay both events. No extra receipt should arrive.
2. Fail a renewal twice. Expect one warning with the original deadline in the studio's time zone. Pay before the deadline and confirm the paid receipt arrives and no pause email follows.
3. Leave a separate renewal unpaid through its deadline. Confirm a new booking and a new session with no earlier appointment are refused, a treatment, laser entry or block on an existing session is still accepted, the owner can still open Billing, and the next worker run sends one pause notice. Pay the invoice and verify booking resumes in the same studio.
4. The worker reports provider acceptance separately from inbox delivery. On a provider timeout it retries with the same message key. An eligible, unconfirmed send older than 23 hours makes the worker report a failure for reconciliation. If delivery is still ambiguous, or the original payload changed, reconcile the provider's send record before manual recovery. Read the outbox using a trusted operator connection. Do not paste recipient addresses or hosted invoice links into logs.

## Access rules once billing stops (decided)
Staff can always document care already given and finish sessions already under way. When a cancellation takes effect, or the seven-day non-payment grace ends, only a new booking and a new unscheduled session are refused. Existing records stay viewable, editable and exportable, and Billing stays available. A pending cancellation is shown to the owner only; staff see the operational status once it is effective. Abandoned signup attempts are deleted 30 days after their last activity (`/api/cron/subscription-retention`); paid studios, Stripe-linked rows and any invoice or notice are kept.
